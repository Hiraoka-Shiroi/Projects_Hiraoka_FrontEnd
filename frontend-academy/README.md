# Frontend Academy

Личная учебная среда на русском языке: **220 уроков, 15 этапов A–O, 12 проектных заданий**. Подробно подготовлены уроки **1–9**, включая короткие шаги, запускаемые примеры и самостоятельные задания. Остальные уроки содержат конкретную карту; подробные материалы добавляются последовательно.

Работают настоящая регистрация, вход и хранение прогресса на сервере Node.js с SQLite. Новый аккаунт начинает с урока 1. При регистрации Hiraoka может перенести прежние данные: исторически пройденные уроки 1–8, текущий урок 9, заметки и черновики. Пароль пользователь выбирает сам. Публичный хостинг ещё не подключён: для входа через интернет с других устройств разместите приложение по [DEPLOYMENT.md](DEPLOYMENT.md).

Вся разработка находится в `frontend-academy`. Соседняя исходная папка `Frontend` — строго только для чтения. Исходные конспекты не переписаны. Реальные номера сохранены: **2 — арифметика, 3 — типы данных**.

## Быстрый запуск в Windows

Нужен **Node.js 24+** с npm. Из PowerShell:

```powershell
Set-Location -LiteralPath 'C:\Users\Hiraoka\Desktop\Программирование\frontend-academy'
node --version
npm.cmd ci
npm.cmd run dev
```

Откройте **http://127.0.0.1:4173/** и оставьте терминал открытым. Остановка — `Ctrl+C`. Для следующего запуска достаточно `npm.cmd run dev`. Можно дважды щёлкнуть `Запустить академию.cmd`: он выбирает нужный каталог и использует `npm.cmd`.

Если PowerShell пишет «невозможно загрузить npm.ps1, выполнение сценариев отключено», используйте `npm.cmd` вместо `npm`. Менять политику выполнения не требуется. Команды выполняются внутри `frontend-academy`, где лежит `package.json`.

Порт фиксирован: если 4173 занят, остановите предыдущий сервер. Dev и production по умолчанию работают с одной базой `data/academy.sqlite` и одним адресом; не запускайте их одновременно. Для готовой сборки вместо dev:

```powershell
npm.cmd run build
npm.cmd run start
```

## Запуск в Linux Mint

Установите Node.js 24+ с npm ([официальная загрузка](https://nodejs.org/en/download)). Перенесите проект с `package-lock.json`, без Windows-папки `node_modules`, затем:

```bash
cd ~/projects/frontend-academy
node --version
npm ci
npm run dev
```

Адрес тот же: **http://127.0.0.1:4173/**. Для production используйте `npm run build`, затем `npm run start`. Запуск на Linux Mint в текущей Windows-сессии не выполнялся. Требуется Node.js 24+ из-за встроенной SQLite, даже если отдельные инструменты допускают более старую версию.

## Первый вход и ваши данные

1. Откройте курс в прежнем браузере по `http://127.0.0.1:4173/`.
2. На регистрации задайте имя, логин и свой пароль от 12 символов. Если найдена прежняя копия, оставьте «Перенести мой текущий прогресс». При желании сначала скачайте её JSON. Старый ключ не удаляется.
3. Дождитесь «Сохранено в аккаунте». Обычный вход восстанавливает серверные данные; отдельные аккаунты имеют отдельный прогресс.
4. После размещения приложения открывайте один HTTPS-адрес на всех устройствах. Если новый сервер получил пустую базу, сначала перенесите базу или экспорт/импорт JSON по инструкции размещения.

Восстановления пароля через email пока нет. Браузер хранит HttpOnly cookie сеанса до 7 дней, а пароль проверяется сервером по scrypt-хешу с индивидуальной солью. Готового аккаунта с выдуманным паролем нет.

## Стандартные команды

В Windows используйте `npm.cmd` вместо `npm`.

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Разработка с тем же account API; loopback, порт 4173 |
| `npm run typecheck` | Строгая проверка TypeScript |
| `npm run build` | Проверка типов и сборка интерфейса в `dist` |
| `npm run start` | Сервер аккаунтов и готовой сборки; сначала build |
| `npm run preview` | Тот же production-сервер; сначала build |
| `npm test` | Проверки карты, контента, валидации и реального account API |
| `npm run test:e2e` | Браузерные сценарии на отдельном тестовом сервере 4175 |
| `npm run check:source` | SHA-256 аудит исходного Frontend; запись только отчёта в academy/docs |
| `node materials/9_функции_по-шагам.js` | Запуск коротких разобранных примеров функций |

Браузерные тесты не используют рабочую базу: сервер и временные SQLite-файлы изолированы. В Windows Playwright использует установленный Microsoft Edge. Для Linux один раз установите Chromium и необходимые системные пакеты:

```bash
npx playwright install --with-deps chromium
npm run test:e2e
```

Установка системных пакетов может запросить пароль администратора. Снимки интерфейса находятся в `docs/screenshots`, сведения о падениях — в `test-results`. Фактические результаты проверок записываются в [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Как учиться

- **Главная:** текущий урок, личные цели, история, проверки, повторения и активные проекты.
- **Карта:** все 220 уроков с зависимостями, результатами и критериями; просмотр будущего урока не подтверждает его прохождение.
- **Урок:** «По шагам» показывает одну короткую идею и мини-попытку; «Все задания» содержит самостоятельную практику; «Справочник» — подробную теорию и полный `.js`-конспект. Ранние уроки также доступны для повторения.
- **Проекты:** 12 постановок с требованиями, сценариями, архитектурой, этапами, приёмкой и полями вашей реализации.
- **Мой прогресс:** доказательства навыков, слабые места, журнал ревью, экспорт и проверяемый импорт JSON.

**Ctrl+K / Cmd+K** открывает поиск по урокам, навыкам, проектам и разделам. Стрелки выбирают результат, Enter открывает, Escape закрывает. Примеры можно копировать. Попытки, заметки и вопросы сохраняются в аккаунте; пакет для ревью можно скачать или скопировать для чата.

Пояснение вывода примера и самопроверки — тренировка, они не запускают ученический код и не присваивают уровень. Собственный JavaScript запускайте в Node.js. Приложение не содержит проверяющего AI/API и не удостоверяет авторство решений.

Для нового статуса «Пройден» нужны все задания/критерии, доказательство решения, выполненные предпосылки и **последнее принятое ревью самостоятельной работы**. Исторические отметки Hiraoka за 1–8 сохраняются отдельно. Ревью записывает человек после действительной проверки кода. Новое ревью «Нужна доработка» снимает приёмку и переводит закрытый урок в повторение.

Освоение независимо от статуса: 0 — не оценено, 1 — знакомство, 2 — базовое понимание, 3 — самостоятельное применение, 4 — уверенное применение в проекте. Для положительного уровня нужны доказательства, для 3–4 — принятое самостоятельное ревью, для 4 — проект и объяснение решений. Счётчик уроков не вычисляет уровень. Даты повторений и ревью используют Asia/Tashkent.

**Урок 9 не закрывается чтением, а урок 10 не начинается до принятой практики урока 9.** Самостоятельные задачи не выдаются с готовыми решениями. Сначала попытка ученика, затем подсказка и проверка.

## Хранение и резервные копии

Основная копия аккаунтов находится в `data/academy.sqlite` на запущенном сервере. При размещении задайте постоянный приватный каталог через `ACADEMY_DB_PATH`; он не должен пропадать при обновлении. Сервер принимает только валидный прогресс и сверяет ревизию, чтобы другая вкладка или устройство не перезаписали новые данные незаметно.

Браузер сохраняет восстановительную копию отдельно для каждого аккаунта под ключом `frontend-academy.account.<id>.progress.v1`. Старый ключ `frontend-academy.progress.v1` читается для добровольного переноса при регистрации. Он не служит общей базой аккаунтов и не удаляется.

- Локальная копия обновляется с задержкой 250 мс, серверная синхронизация — 500 мс после изменений. Перед уходом со страницы локальная очередь сохраняется; при отсутствии сети сервер может ещё не получить изменения.
- Индикатор различает серверное сохранение, синхронизацию и наличие локальной копии. При сбое можно повторить сохранение и скачать JSON.
- При конфликте сначала сохраните свою копию, затем загрузите серверную версию. Автоматического слияния несовместимых правок нет.
- Повреждённая локальная запись не перезаписывается молча: её можно скачать для восстановления. Ошибки доступа и переполнения хранилища показываются явно.
- JSON до 5 МБ проверяется целиком: версия, IDs, поля, чек-листы, доказательства и приёмка. Диалог показывает сводку; применение заменяет прогресс выбранного аккаунта после успешной серверной записи. До импорта сделайте экспорт.
- Неизвестные поля отбрасываются; неподдерживаемые версии и противоречивые данные отклоняются. Старые копии читаются с миграцией необязательных полей, без выдуманных доказательств.
- Ссылки проектов допускают только HTTP/HTTPS; текст заметок выводится через React.

Очистка браузера не удаляет синхронизированный серверный прогресс. Несинхронизированная локальная копия принадлежит конкретному браузеру и origin, поэтому до очистки или смены устройства скачайте JSON. Экспорт одного аккаунта не содержит пароль и не заменяет копию всей SQLite-базы. Подробный запуск с HTTPS, Docker, перенос базы и резервное копирование: [DEPLOYMENT.md](DEPLOYMENT.md).
