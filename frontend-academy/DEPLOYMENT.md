# Запуск аккаунтов и размещение курса

Регистрация, вход и синхронизация работают через сервер Node.js и SQLite. Сейчас сервер находится на вашем компьютере. Чтобы войти с другого устройства через интернет, нужно разместить **всё приложение вместе с сервером**, а затем открывать на обоих устройствах один HTTPS-адрес. Загрузка только папки `dist` на статический хостинг не запустит аккаунты.

Хостинг и домен в этой работе не приобретались, публичный адрес не создан. Ниже подготовлены команды для своего компьютера и будущего сервера. Linux и Docker в текущей Windows-сессии не запускались.

## 1. Локальный запуск в Windows

Нужен Node.js **24 или новее** с npm. Из-за встроенного `node:sqlite` Node.js 22 для этой версии приложения не поддерживается. Проверьте версию:

```powershell
Set-Location -LiteralPath 'C:\Users\Hiraoka\Desktop\Программирование\frontend-academy'
node --version
npm.cmd ci
npm.cmd run dev
```

Откройте **http://127.0.0.1:4173/**. Оставьте терминал открытым. Остановка — `Ctrl+C`. Использование `npm.cmd` обходит ошибку PowerShell о запрещённом `npm.ps1`; менять ExecutionPolicy не требуется.

Для запуска готовой сборки сначала остановите dev, затем:

```powershell
npm.cmd run build
npm.cmd run start
```

Dev и production по умолчанию используют одну локальную базу `data/academy.sqlite`. Не запускайте их одновременно на порту 4173. `npm.cmd run preview` запускает тот же production-сервер и также требует готовой сборки.

## 2. Первый личный аккаунт и перенос истории

1. Откройте курс в том браузере и по тому же адресу `http://127.0.0.1:4173/`, где учились раньше.
2. Во вкладке регистрации укажите имя, уникальный логин и **свой** пароль от 12 до 128 символов. Готового пароля или заранее созданного аккаунта Hiraoka нет.
3. Если найдена старая копия, оставьте «Перенести мой текущий прогресс». Так сохранятся прежние статусы, заметки, черновики и ревью. Старую браузерную копию приложение не удаляет. Можно отдельно скачать её JSON.
4. Для Hiraoka исторические уроки 1–8 остаются пройденными, урок 9 — в процессе. Их новые материалы можно перечитывать. Аккаунт без переноса начинает с урока 1.
5. Дождитесь надписи «Сохранено в аккаунте». После размещения сайта войдите на другом устройстве с теми же логином и паролем на **том же сервере**.

База на компьютере и новая пустая база на хостинге — разные хранилища. Для переноса на хостинг либо перенесите остановленную базу целиком по разделу 7, либо зарегистрируйтесь на новом сервере и импортируйте экспорт JSON в «Мой прогресс». Экспорт переносит учебные данные, но не пароль и не сеансы входа. Не регистрируйте повторно одинаковый логин в уже перенесённой базе — войдите в существующий аккаунт.

Сброса забытого пароля через email сейчас нет. Сохраните пароль в своём менеджере паролей. Действующий сеанс хранится в HttpOnly cookie до 7 дней; можно войти одновременно на нескольких устройствах.

## 3. Локальный запуск в Linux Mint

Перенесите папку проекта с `package-lock.json`, без Windows-папки `node_modules`. Установите Node.js 24+ для своей архитектуры с [официальной страницы Node.js](https://nodejs.org/en/download), затем:

```bash
cd ~/projects/frontend-academy
node --version
npm ci
npm run build
npm run start
```

Откройте **http://127.0.0.1:4173/**. Для разработки вместо двух последних команд используйте `npm run dev`. Обычные команды npm в Linux не требуют суффикса `.cmd`.

## 4. Настройки production-сервера

| Переменная | По умолчанию | Для размещения |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | За локальным reverse proxy оставьте `127.0.0.1`; внутри контейнера — `0.0.0.0` |
| `PORT` | `4173` | Внутренний порт Node.js |
| `APP_ORIGIN` | `http://127.0.0.1:4173` | Точный публичный адрес, например `https://academy.example.com`, без пути |
| `ACADEMY_DB_PATH` | `data/academy.sqlite` внутри проекта | Абсолютный путь в постоянном приватном каталоге, например `/var/lib/frontend-academy/academy.sqlite` |
| `NODE_ENV` | Не задана | `production` |

Задайте настройки через окружение процесса или панель хостинга. Приложение самостоятельно **не читает `.env`**. В PowerShell они задаются как `$env:APP_ORIGIN = 'https://academy.example.com'`, в Linux — `export APP_ORIGIN='https://academy.example.com'`.

Публичный адрес должен совпадать с `APP_ORIGIN`, включая протокол и нестандартный порт. `localhost` и `127.0.0.1` отличаются. Несовпадение вызовет сообщение «Запрос должен исходить с сайта курса». HTTPS в `APP_ORIGIN` включает Secure cookie; открытие такого сервера по HTTP не подходит для входа.

Для небольшого личного сервера выделите от 512 МБ свободной памяти процессу; парольное хеширование может одновременно занимать около 256 МБ дополнительно к приложению. Начальная регистрация открыта всем посетителям. Этот вариант предназначен для небольшого курса: лимит входа считает подключения по сетевому IP, а за reverse proxy общий IP прокси объединяет посетителей. Для публичного большого сервиса дополнительно настройте лимиты на прокси и процесс восстановления аккаунтов.

## 5. Linux-сервер с HTTPS

Нужен сервер с постоянным диском, Node.js 24+ и доменом, направленным на сервер. Каталог приложения и базу должен обслуживать отдельный непривилегированный пользователь. Не используйте временную файловую систему: при пересоздании сервиса она потеряет аккаунты.

Сначала установите зависимости и соберите приложение в его каталоге:

```bash
npm ci
npm run build
npm ci --omit=dev
```

Последняя команда оставляет runtime-зависимости, включая `tsx`. Сам сервер читает `server/` и общие модули `src/`, поэтому вместе с `dist` сохраняйте также `server`, `src`, `package.json`, `package-lock.json` и установленные runtime-зависимости.

Настройте запуск через службу systemd или process manager вашей площадки. Пример `/etc/systemd/system/frontend-academy.service`; замените имя пользователя, пути и домен своими значениями:

```ini
[Unit]
Description=Frontend Academy
After=network.target

[Service]
Type=simple
User=academy
Group=academy
WorkingDirectory=/opt/frontend-academy
Environment=NODE_ENV=production
Environment=HOST=127.0.0.1
Environment=PORT=4173
Environment=APP_ORIGIN=https://academy.example.com
Environment=ACADEMY_DB_PATH=/var/lib/frontend-academy/academy.sqlite
StateDirectory=frontend-academy
StateDirectoryMode=0700
ExecStart=/usr/bin/node --import tsx server/index.ts
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true
UMask=0077

[Install]
WantedBy=multi-user.target
```

`ExecStart` должен содержать абсолютный путь вашего Node.js 24+ (`command -v node`). systemd не загружает оболочку nvm. Служба предполагает, что пользователь `academy` уже создан и имеет право читать каталог проекта; `StateDirectory` создаёт для него постоянный каталог базы.

На том же сервере настройте HTTPS reverse proxy. Например, при установленном Caddy и доступных портах 80/443 фрагмент Caddyfile:

```caddyfile
academy.example.com {
    reverse_proxy 127.0.0.1:4173
}
```

После настройки домена и proxy включите службу обычными средствами systemd:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now frontend-academy
sudo systemctl status frontend-academy
```

Внешнему пользователю нужен только HTTPS-порт proxy. Не публикуйте наружу каталог `data` или порт базы. Приложение использует SQLite-файл, отдельный сервер базы не нужен. Проверяйте через публичный HTTPS-адрес регистрацию, выход, повторный вход и сохранение заметки на двух устройствах.

## 6. Вариант с Docker

`Dockerfile` собирает интерфейс и запускает Node.js 24 от пользователя `node`. База вынесена в отдельный том. Проверка локально:

```bash
docker build -t frontend-academy .
docker volume create frontend-academy-data
docker run -d --name academy --restart unless-stopped \
  -p 127.0.0.1:4173:4173 \
  -e APP_ORIGIN=http://127.0.0.1:4173 \
  -v frontend-academy-data:/app/data \
  frontend-academy
```

Откройте `http://127.0.0.1:4173/`. Для размещения задайте в этой команде свой `APP_ORIGIN=https://academy.example.com` и настройте HTTPS proxy с предыдущего раздела. Команда с `\` записана для Linux shell; в PowerShell выполните её одной строкой. Том `frontend-academy-data` необходимо сохранить при обновлении контейнера. Не используйте `docker volume rm` для рабочего тома и не запускайте несколько экземпляров приложения с разными копиями базы, ожидая общей синхронизации.

При обновлении соберите новый образ, остановите прежний контейнер, сделайте копию данных, затем пересоздайте контейнер с **тем же томом и окружением**. `docker logs academy` показывает журнал, `docker stop academy` корректно останавливает сервер. Docker-образ и конфигурация подготовлены, но Docker-сборка здесь не выполнялась.

## 7. Резервная копия, перенос и восстановление

Есть две разные копии:

- Экспорт JSON в «Мой прогресс» содержит учебные данные одного аккаунта. Его можно импортировать после входа на другом сервере. До импорта скачайте текущий JSON: импорт заменяет данные выбранного аккаунта.
- Серверный каталог базы содержит все аккаунты, хеши паролей и сеансы. Его копия нужна для полного восстановления. Храните её приватно, отдельно от сайта и исходников.

Самый простой корректный способ копирования SQLite — **сначала остановить единственный сервер**, затем скопировать весь каталог базы, включая возможные `academy.sqlite-wal` и `academy.sqlite-shm`. Не копируйте только основной файл работающей WAL-базы.

Локально в Windows остановите сервер `Ctrl+C`, затем из корня проекта:

```powershell
$academyBackup = Join-Path $env:USERPROFILE ('academy-backups\' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $academyBackup -Force
Copy-Item -LiteralPath '.\data' -Destination $academyBackup -Recurse
```

Для контейнера остановите его, скопируйте каталог и снова запустите:

```bash
docker stop academy
mkdir -p "$HOME/academy-backups/2026-10-18"
docker cp academy:/app/data/. "$HOME/academy-backups/2026-10-18/"
docker start academy
```

При восстановлении остановите сервер, сохраните отдельную копию его нынешнего каталога, замените каталог целиком выбранной резервной копией, восстановите права владельца службы и запустите сервер. Для контейнера восстановите файлы в тот же постоянный том с владельцем `node` (UID 1000). Не смешивайте WAL/SHM одной копии с основным файлом другой. После восстановления проверьте вход и данные; устройства с несинхронизированной локальной копией могут показать конфликт — сначала экспортируйте их JSON.

## 8. Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| PowerShell блокирует `npm.ps1` | Используйте `npm.cmd`, переходите в `frontend-academy` |
| Порт 4173 занят | Остановите предыдущий dev/start; не запускайте два сервера |
| Страница просит сначала выполнить build | Из корня проекта выполните `npm.cmd run build` или `npm run build` в Linux |
| Нет `node:sqlite` | Проверьте `node --version`: нужен Node.js 24+ |
| Вход работает локально, но не на домене | Проверьте точный `APP_ORIGIN`, HTTPS, proxy и cookie |
| На другом устройстве пустой прогресс | Убедитесь, что это тот же адрес и аккаунт, дождитесь серверного сохранения |
| Слишком много попыток входа | Дождитесь указанного времени; лимит действует 15 минут, за proxy он может быть общим |
| Конфликт версий | Скачайте локальный JSON, загрузите серверную версию и перенесите нужные изменения осознанно |
| Нет связи | Сохраните JSON; несинхронизированные изменения ещё не доступны другому устройству |

Сервер валидирует данные и не принимает устаревшую ревизию поверх новой. После восстановления сети синхронизация повторяется; JSON остаётся независимым способом переноса. Эти проверки не заменяют резервные копии серверного диска.
